  Publish On Receive
   As the name suggests, the Publish On Receive feature will cause the client to send message(s)
   upon reception of a message using the calling thread and independently of the publisher thread.
   The user must specify the number of message its client(s) must send upon reception of a message using
   the -nmpr flag. By default, if no destination is provided, the message will be sent back to the
   destination from which the message was received. It is possible to specify multiple types of
   destinations in the same query (i.e. both -porql and -portl can be used simultaneously).
   It is also possible to vary the message size of each message sent using the -pormsa argument.
   The Publish on Receive feature is compatible with the -ats argument. The client will use the
   transacted session to publish if a message was received from a transacted session. It is important
   to note that the client will only commit or rollback upon reception of the defined number of messages.
   In other words, specifying the arguments "-ats=2 -nmpr=2" would result in transactions 
   containing 6 messages (2 received + 4 published).

   -nmpr int        Number of messages to publish on receive. Specifies the number of messages
                     to publish upon reception of a message. Default: 0
   -portl list      List of topics (comma separated) to be used for publishing upon message reception.
   -porql list      List of queues (comma separated) to be used for publishing upon message reception.
   -pormt string    Message type, one of {direct|nonpersistent|persistent}. Default: direct
   -pormsa list     Comma separated size list in bytes for auto-generated binary attachment portion.
   -porrm           If flag is set, the first message published on receive will be the message received
                    but only if it has a reply-to destination set. The message destination will be set
                    as the reply-to destination and the reply-to destination will be cleared before the
                    message is published.

                     by appending '<TOPIC_END/>qos=<value>' to your topic (e.g.'-stl=test_topic<TOPIC_END/>qos=1')
  -mcs bool          MQTT flag indicating whether the session should be cleaned.
                     Default: 1 (true); Accepted values: 1 (true), 0 (false)
  -mwmt string       MQTT Will Message Topic. MQTT topic on which the will message will be sent.
  -mwms int          MQTT Will Message Size. Default: 0 
  -mwmq int          MQTT Will Message Quality of Service (QoS). Default: 0 
  -mwmr              MQTT Will Message Retained. MQTT flag indicating whether the Will Message should be retained.
  -mssldhv           MQTT SSL Disable Hostname Verification.
                     Disabling SSL hostname verification results in a less secure connection but allows for the use of MQTT client certificates without a Subject Alternative Name configured for testing purposes.

  Next Gen Specific Properties: 
  -pbp list         Publisher back pressure types. Options are [elastic, reject, wait, no] (default wait)
                    If multiple backpressure types are specified they will be applied to producers in each
                    client in a round robin method. Each backpressure type will use the same buffer size.
                    ('No' uses the API default). Example usage: -bp=elastic,reject,wait,reject
  -pbpb int         Publisher back pressure buffer size for reject or wait (default 10000)
  -sbp string       Subscriber back pressure type. Only applies to direct receiver.
                    Options are [elastic, oldest, latest] (default elastic)
  -sbpb int         Subscriber back pressure buffer size for drop latest or oldest (default 10000)
  -rs int           Receiver sleep time in seconds after processing message.
                    Used to simulate a slow receiver for backpressure testing (default 0, no sleeping)

  Tracing Specific Properties: 
  -tmd              Trace message dump. When printing messages, the payload will be decoded
                    from the protobuf to show trace data (For debugging telemetry queue, also sets -md to true)
  -tdc              Enable trace decode and time checking, also show stats at the end.

  -tsn string       Override service name from sdkperf_java/jms to given value (Used in create/send/process spans)
  -tcc              Inject creation context with pre-defined values for trace ID, sampled ID, trace state and sampled flag
                    into published messages and generate/export spans at the same time.
                    Using the -tcctid, -tccsid, -tccts, or -tccs options will result in a creation context being injected
                    into published messages. The options (or their defaults) will all be used in the same context.
                    However, no span will be generated for the publisher as a result.
  -tcctid string    Creation context injected into messages will have specified trace ID,
                    must be specified as 32 hex characters to be converted into 16 bytes. (Default: Random 16 byte hex)
  -tccsid string    Creation context injected into messages will have specified span ID,
                    must be specified as 16 hex characters to be converted into 8 bytes. (Default: Random 8 byte hex)
  -tccts  string    Creation context injected into messages will have specified trace state.
                    Format: "key1,val1,key2,val2" (Default: Empty)
  -tccs             Creation context injected into messages will set the sampled flag. (Default: False).
  -bag    string    Creation context injected into messages will have specified baggage, Format: "key1=val1,key2=val2" (Default: Empty).
  -ttc              Inject transport context with pre-defined values for trace ID, sampled ID, trace state and sampled flag
                    into published messages and generate/export spans at the same time.
                    Using the -ttctid, -ttcsid, -ttcts, or -ttcs options will result in a transport context being injected
                    into published messages. The options (or their defaults) will all be used in the same context.
                    However, no span will be generated for the publisher as a result.
  -ttctid string    Transport context injected into messages will have specified trace ID,
                    must be specified as 32 hex characters to be converted into 16 bytes. (Default: Random 16 byte hex)
  -ttcsid string    Transport context injected into messages will have specified span ID,
                    must be specified as 16 hex characters to be converted into 8 bytes. (Default: Random 8 byte hex)
  -ttcts  string    Transport context injected into messages will have specified trace state.
                    Format: "key1,val1,key2,val2" (Default: Empty)
  -ttcs             Transport context injected into messages will set the sampled flag. (Default: False).
  -tcrc             Copy receive context into a new span to be exported. (Default: False).
  -tecip  string    Trace Exporter Connection String, point to a OTLP receiver for spans generated 
                    via -tcc, -ttc, or -tcrc. Example: "http://192.168.0.1:4317"
                    (Default: Empty, uses NoOpExporter instead)
  -tebs int         Trace Exporter Batch Size. (Default: 5).
  -tesd int         Trace Exporter Schedule Delay in millisecond. (Default: 100ms).
  -teqs int         Trace Exporter Queue Size. (Default: 2048).
